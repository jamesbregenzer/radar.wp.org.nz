# Core Trac CSV recovery contract

This repair hardens acquisition and validation of the existing configured Core Trac CSV sources. For a configured named Trac report, `source_defined` means the acquisition records the exact configured report CSV URL as the requested source and accepts the named report membership as the source's semantic definition. The recorded URL is provenance; the collector does not independently inspect or attest to the response URL. It does not mean every row was independently checked against keyword predicates. Where row keywords are present, configured required and forbidden keyword rules are checked using exact normalized tokens. Missing or malformed keyword evidence does not prove that a forbidden keyword is absent. Query-defined sources continue to require their configured row-level semantics.

Core CSV acquisition uses bounded per-source attempts and a separate finite run budget. Each Core source has a 90-second budget shared across at most two attempts; each wait is bounded by the remaining source budget. Wave 2 HTTP requests retain a separate 45-second maximum per-request timeout. The default whole-run acquisition budget is 45 minutes. These are best-effort monotonic deadlines: safe browser cleanup and receipt writing can extend wall-clock completion, and diagnostics report observed elapsed time separately from the budget. A timeout alone does not establish that a human-verification page was shown.

The repair records degraded or unavailable source coverage while retaining healthy-source observations. It does not verify or restore any scheduler, current operator, or production run. No scheduler restoration has been verified.
